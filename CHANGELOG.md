# Changelog

## [Unreleased]

### Added

- Surface lighting now evaluates a real BRDF instead of adding flat light on top of the frame. A new prepass (`VRSLSurfacePrepass`, driven by the `Hidden/VRSL-URP/SurfaceProperties` shader assigned to `surfacePropertiesShader` on either manager) captures per-pixel albedo, smoothness and metallic into `_VRSLAlbedoTexture` / `_VRSLMaterialTexture`, and the lighting pass runs URP's own `InitializeBRDFData` + `DirectBRDF` against them. A lit surface now keeps its texture colour rather than washing towards white, glossy surfaces pick up a specular highlight, and metals respond as metals. The prepass renders opaque geometry through `DrawingSettings.overrideShader`, so each renderer keeps its own material's property values — URP Lit, Poiyomi URP, lilToon URP and anything else following the `_BaseMap`/`_BaseColor` or `_MainTex`/`_Color` convention contributes with no shader-author involvement. Costs one extra opaque geometry pass; leaving `surfacePropertiesShader` empty skips it and lights every surface as a neutral mid-grey dielectric.

- Screen-space tiled light culling (`VRSLLightCull.compute`, assigned to `lightCullShader` on either manager). A compute pass builds a per-tile list of the fixtures whose range reaches each 16×16 screen tile, and both the surface and volumetric passes iterate that list. Per-pixel cost now tracks lights-per-tile rather than the scene's total fixture count; the volumetric pass benefits most, since its inner loop previously ran the full fixture list once per raymarch step. Tile frusta span the camera's full depth range so one list serves both passes, and tiles are built per eye under single-pass instanced VR. Capped at 64 fixtures per tile. Leaving `lightCullShader` empty falls back to iterating every fixture.

- `DMXFixtureType.StaticPointLight` — a static fixture archetype on `VRStageLighting_DMX_RealtimeLight` that emits as an omnidirectional point light. The manager forces point-light mode for the type and the inspector hides the spot, cone, pan/tilt, gobo, and output-axis fields, so authoring a light bar or par as a point source is a one-pick preset rather than a manual toggle. Runtime behaviour matches a static par with `isPointLight` enabled — the DMX path already carried the point/spot flag end to end, so the type adds authoring ergonomics, not new rendering.
- `use5ChannelMode` on `VRStageLighting_DMX_RealtimeLight` — decodes DMX using the compressed 5-channel static layout (dimmer +0, RGB +1/2/3, strobe +4) instead of the standard 13-channel layout (dimmer +5, RGB +7/8/9, strobe +6), matching the fixture-body surface shader's `_5CH_MODE`. The render-pass light previously only decoded the 13-channel layout, so fixtures patched 5 channels apart cross-talked — each light read its neighbours' channels. The flag rides a reserved slot of the per-fixture GPU config, so there is no buffer-stride change; gobo/spin reads (+10/+11) are suppressed in 5CH since those channels belong to the next fixture.

- `VRSL_URPLightManager` now publishes its assigned DMX grid CRTs as the `_VRSLU_DMX*` shader globals that fixture-body surface shaders sample, so the manager alone drives both the render-pass lights and the fixture-body emissive — `VRSL_LocalUIControlPanel` is no longer required to set those globals for the URP path. A new `dmxStrobeTimerTexture` slot supplies the StrobeTimings CRT (`_VRSLU_DMXGridStrobeTimer`) that the StrobeOutput CRT's decode shader needs to compute the strobe gate. The manager also forces its assigned CustomRenderTextures into Realtime update mode, so it fully replaces `VRSL_LocalUIControlPanel` for the URP path.
- The DMX light manager now derives a fixture's light origin from the centre of the fixture-body mesh it drives (`fixtureShellRenderers[0].bounds.center`) when no `lensTransform` is assigned, before falling back to the component's own transform. This places the light at the lit geometry even when the fixture component sits away from it — e.g. fixtures parked at a shared root while their bar sub-meshes are spread across the scene (common in imported environments where the bars share one transform, so both the component transform and a `lensTransform` pointed at the bar resolve to the root).

- Optional Basis integration (`Runtime/Integrations/Basis/`) that feeds the DMX decode chain from a `BasisMediaPlayer` video stream, so a DMX-over-video signal drives the rig without a capture camera filming a screen quad. `BasisVideoToVRSLDMX` publishes the player's `OutputTexture` as a shader global by reference and republishes only when the texture identity changes, so the native decoder's in-place updates reach the interpolation CRT with no per-frame copy. `BasisVideoRenderTextureOutput` covers the case where the grid occupies part of a larger frame: it blits the player output into the RAW-grid RenderTexture through four source UVs, one per corner, which expresses crop, roll, flip and shear together, and its inspector drags those corners over the live frame (or a still) and can bake a starting point from an existing camera and screen quad. Both fold the player's `OutputFrameIsTopLeftOrigin` into their sampling, so a client whose GPU delivers frames top-left origin decodes the same grid as one that doesn't. The pair compiles into its own `Towneh.VRSL.URP.Basis` assembly, constrained on `com.basis.mediaplayer` and `com.cnlohr.cilbox`; in a project without them the assembly is skipped and the package is unchanged.

- Screen-space contact shadows, off by default via `contactShadowStrength` on either manager. Each light marches the depth buffer from the lit pixel towards the fixture, so an avatar standing in a beam now shadows the floor at its feet. Contact shadowing rather than shadow mapping: only geometry the camera can see, and only within the trace distance — a wall across the room still doesn't block a beam. It's the most expensive term in the lighting loop, which is why it's opt-in.

### Removed

- The `Directional Light (For Depth)` prefab, and its instance in all three URP realtime example scenes. It existed to make `_CameraDepthTexture` appear: under the Built-in pipeline a shadow-casting directional light forces the camera to produce a depth texture, which the legacy volumetric mesh shaders sample for their depth fade. URP has no such coupling — the depth texture comes from the URP Asset's Depth Texture setting or from a pass calling `ConfigureInput`, which every VRSL pass that reads depth already does. The light was contributing nothing, and because it shipped with hard shadows enabled it was drawing a main-light shadow map every frame for a light whose colour is black at 0.001 intensity, which is exactly the per-light shadow cost the URP light path exists to avoid. **If you copied this prefab into your own scene, delete it** — depth still works without it, verified with no lights in the scene at all.

### Changed

- Surfaces hidden by a shader's own visibility logic no longer pick up VRSL light through the wrong albedo. The albedo prepass draws through `DrawingSettings.overrideShader`, which replaces the material's shader outright, so anything that decides visibility inside that shader never runs — Poiyomi's UV Tile Discard being the case that surfaced it. In its default Vertex mode Poiyomi returns NaN from its vertex program, collapsing the triangle in the passes that feed `_CameraDepthTexture`, but the prepass still drew the geometry; the lighting pass then took its position from the camera's depth (the surface behind) and its albedo from the prepass (the discarded avatar), so the hidden shape reappeared as lit colour. The prepass now publishes its depth as `_VRSLSurfaceDepthTexture` and the lighting pass ignores albedo wherever that disagrees with the camera's depth, falling back to the neutral dielectric it already uses for surfaces with no prepass data. Compared in linear eye space against a tolerance proportional to viewing distance, since the two depths come from different compilations of the same transform and so agree closely rather than exactly. Also covers custom alpha clips and vertex displacement, which had the same mismatch for the same reason.
- `volumetricStepCount` defaults to 24 rather than 32, on both managers and all four URP light-manager prefabs. Now that each light's span is bounded to its cone, every step lands inside the beam, so the same visual quality needs fewer of them — 16 held up on a rig of 60° spots at 20 m range. Scenes that set the field explicitly are unaffected. What governs the floor is metres of cone per step rather than the count alone, so wide cones, long beams and dense haze still want more.
- Volumetric cones no longer show structured stepping. Each light is marched across the part of the view ray that falls inside its cone, found by intersecting the ray with the light's bounding sphere and then narrowing that to the cone via `VRSL_NarrowSpanToCone`. Marching the sphere alone spends the step budget mostly outside the beam — at a 20 m range the chord runs to 40 m and includes the whole backward hemisphere, while a ray crossing a beam near the lens covers well under a metre of lit space — so a handful of samples carried the whole result. That is quadrature error large enough that the dither can't conceal it, and it surfaced as whatever pattern the dither carried rather than as fine grain, worst near a fixture head where the cone is narrowest relative to its sphere. Point lights fill their sphere and keep the sphere span. Because the span is now tight, `volumetricStepCount` can usually go well below its default before stepping is visible.
- The half-res volumetric upsample reconstructs smooth gradients correctly. Taps were centred on the nearest half-res texel, so all four full-res pixels of a 2×2 block resolved to identical taps and weights and the composite was constant across the block, which terraces a gradient into contours. Weights now follow the pixel's true sub-texel position through a separable tent of radius 1.5, chosen so a tap reaches zero weight as the centre texel flips and the reconstruction stays continuous. The depth term is also fixed: it weighted by `1/(eps + depthDiff)` with `eps` as a divide guard rather than a tolerance, which is unbounded near zero and gave the centre tap a weight orders of magnitude above its neighbours on any non-fronto-parallel surface, collapsing the 3×3 kernel to a point sample. It is now `1/(1 + d²)` against a tolerance proportional to viewing distance.
- The raymarch step dither is interleaved gradient noise rather than a Weyl lattice. `frac(a*x + b*y)` has straight diagonal iso-value contours, so every pixel along one diagonal received an identical step phase and residual stepping streaked into a diagonal weave instead of breaking up. Same cost.
- The volumetric raymarch integrates each light across the span of the view ray that falls inside that light's own range, instead of every light sharing one march from the camera to the opaque surface. A shared march sizes its steps against whatever geometry happens to sit behind a beam, so a cone a few metres from the camera with a distant wall behind it drew one or two samples out of the whole budget, and the jitter that hides banding turned that undersampling into the grain that made `Half` read as dithered. Sample density now follows the beam's own thickness and is independent of scene depth, which is where the visible improvement at `Half` comes from. The per-light budget is the full `volumetricStepCount`, so the worst case costs what the shared march cost; rays that miss a light's bounding sphere now skip it for a few ALU rather than stepping through it, so scenes whose fixtures don't fill the frame get cheaper. With `volumetricUseNoise` enabled the density noise is sampled per light rather than once per shared step, costing a fetch per light per step wherever cones overlap.
- `VRSLLightData` is 64 bytes rather than 80, cutting the buffer traffic of the volumetric inner loop by a fifth. The active flag is gone — a fixture emitting nothing is written with zero intensity, which the readers already had to check — and the light type and gobo slice share `directionAndType.w`. Both packed values are small integers, which floats represent exactly, so nothing loses precision; packing them as halves would have quantised the gobo spin phase and stippled a slow rotation. Shaders read them through `VRSL_LightType`, `VRSL_GoboIndex` and `VRSL_IsActive` in `VRSLLightingLibrary.hlsl`.
- **Breaking:** a DMX fixture at full output is now half as bright. `maxIntensity` is defined as being on the same scale as a URP spot light's Intensity value, which requires the dimmer curve to reach exactly 1 at full DMX. It previously peaked at `curveMod` — 2 on the default curve — so a DMX fixture emitted twice what its `maxIntensity` said, and twice what an AudioLink fixture set to the same number emitted. The curve's shape is unchanged, so the cast light still ramps together with the fixture-body glow. To restore previous brightness, double `maxIntensity` on affected fixtures, or set `curveMod` to 1.
- The gobo wheel is packed on the GPU. `BuildGoboArray` previously did a `ReadPixels` readback and a CPU upload per slot, stalling whenever fixtures were refreshed, and resampled every gobo to 256². Slices are now blitted straight into an array render texture at the resolution of the largest source (clamped to 1024).
- With both the DMX and AudioLink managers active, the surface prepass runs once rather than twice. Its output doesn't depend on which manager drives it, so the DMX manager owns it and the AudioLink manager defers. Saves two opaque geometry draws per camera in dual-manager scenes.

- `VRSLNormalsPrepass` is now `VRSLSurfacePrepass`, since it captures albedo and material data alongside the authored normals. The normals half is unchanged — same `DepthNormals` / `DepthNormalsOnly` shader tags, same `_VRSLNormalsTexture` global.
- Both light passes skip the gobo texture fetch wherever a light already contributes nothing, and the surface evaluation rejects lights outside their range before doing any further work. The gobo fetch is the most expensive part of either inner loop, and a gobo can only ever reduce a light's contribution.

- Package identifier renamed from `net.towneh.vrsl-urp` to `town.mr.vrsl-urp`. All `Packages/net.towneh.vrsl-urp/...` shader include paths and editor/runtime asset-path constants follow the new name. Consuming projects need their manifest entry key updated to `town.mr.vrsl-urp`; local `file:` paths and asset GUIDs are unaffected.
- The DMX screen-reader prefabs (horizontal and vertical) no longer carry a `MeshCollider` on the screen quad, and the quad no longer samples light probes. The control panel prefab has been stripped of the two leftover UdonSharp behaviours it inherited from upstream, along with the button events that targeted them.

### Fixed

- DMX channels past the second in each grid row decoded from the row below. The Built-in path passes its computed row through `IndustryRead(int x, int y)`, truncating it to an integer before scaling into UV; the URP compute port kept the division but dropped the truncation, leaving `frac(channel / 13)` of a row of drift. The inherited `-0.001915` offset absorbed about 0.23 of a row, so the first couple of channels in each row and the exact multiples of 13 kept working while most per-fixture offsets — dimmer at +5, colour at +7/8/9 — read a neighbouring fixture's value, decoding plausible numbers rather than failing visibly.

- A DMX fixture whose colour faded to black while its dimmer stayed up kept visibly emitting: the light's active flag was gated on decoded intensity alone, and the residual near-black RGB got amplified by `maxIntensity` — for point lights whose origin sits on the bar mesh, by strong near-field attenuation too. The flag now also requires a colour channel above `6/255`, which clears the fade residual even at high `maxIntensity`, at the cost of clipping colours dimmer than ~2.4%.
- DMX fixture-body surfaces decoded a black grid while the render passes were active. The grid CRTs were published with `Shader.SetGlobalTexture`, which URP's render graph binds to scene shaders as a 1×1 black fallback — every bar and par surface stayed dark even though the render-pass lights, whose compute binds the CRTs directly, kept working. The compute pass now re-publishes the CRTs via `SetGlobalTextureAfterPass` so the opaque pass samples the live textures. The surface decode also now samples through an explicit point/clamp sampler (a CustomRenderTexture's runtime filter mode frequently resolves to Bilinear regardless of the asset setting, bleeding neighbouring channel cells into the read) and takes its texel size from the manager-published `_VRSLDMXTexelSize` global rather than the texture's auto `_TexelSize`, which Unity overwrites for globally bound textures; the resulting row-UV drift grew down the grid, so the highest-patched fixtures decoded the wrong (often black) cell.
- DMX **point-light** fixtures (`isPointLight` / `StaticPointLight`) were silently masked to near-zero whenever the manager had gobo textures assigned. The compute clamped every fixture's gobo to slot 0, and `SampleGobo` then projected it as a spot cone — returning 0 for the spill behind the light axis and multiplying the front by the (often dark) slot-0 texture. Point lights now keep `goboIdx = -1` (the `SampleGobo` no-op), so their omnidirectional spill is unmasked and scales with intensity as expected. Symptom was a large decoded intensity with no visible scene spill that didn't respond to `maxIntensity`.
- The URP `VRSL_LocalUIControlPanel` custom inspector aborted every repaint with a `FileNotFoundException` because `GetVersion()` read a `Runtime/VERSION.txt` the package never shipped. The throw happened before `base.OnInspectorGUI()`, so none of the panel's serialized fields drew — the CRT source arrays (`DMX_CRTS_Horizontal` etc.) looked empty and couldn't be wired, leaving the `_VRSLU_*` DMX globals unpublished and fixture-body surfaces unlit. `GetVersion()` now guards the read with `File.Exists` and a try/catch fallback, and the package ships `Runtime/VERSION.txt`.

### Known issues

- **Par, blinder, laser, and discoball fixture meshes do not render correctly under single-pass instanced VR.** The mesh body / projection geometry on these fixture types is missing or misplaced in one or both eyes. Moving heads (spots and washes) and the surface lighting and volumetric-cone passes are unaffected. A previous fix (`1746a30`) addressed the same class of issue for the moving-head body / volumetric meshes by routing their shaders through `#pragma multi_compile _ STEREO_INSTANCING_ON STEREO_MULTIVIEW_ON` and making their `DepthOnly` / `DepthNormals` passes SPSI-aware; the par, blinder, laser, and discoball shaders still need the equivalent treatment.

## [0.1.0] — Initial release

### URP Realtime Lights — Unity 6 / URP 17+

The pipeline is four Render Graph passes — all reading the same per-fixture GPU buffer — injected at runtime by the manager MonoBehaviour via `RenderPipelineManager.beginCameraRendering`. No URP Renderer Features required, no URP asset / renderer asset settings touched by the package; co-exists with whatever rendering path, MSAA setting, depth-priming mode, and depth-texture configuration the project uses.

A VRSL-owned normals prepass renders opaque scene geometry with the standard URP `DepthNormals` / `DepthNormalsOnly` shader tags into a VRSL-owned RT, so authored surface normals from any URP-targeted shader (URP Lit, Poiyomi URP, lilToon URP, Mochie URP) come through automatically — avatars and props receive smooth-shaded VRSL light without their authors needing to add anything URP-specific.

- **Compute** decodes per-fixture state (position, direction, colour, intensity, cone, gobo) into a `StructuredBuffer`.
- **DMX** — `VRStageLighting_DMX_RealtimeLight` + `VRSL_URPLightManager`. Decodes the existing CRT chain on the GPU; no per-frame CPU cost per fixture.
- **AudioLink** — `VRStageLighting_AudioLink_RealtimeLight` + `VRSL_AudioLinkURPLightManager`. Reads animated transform directions on the CPU each frame and samples the global `_AudioTexture` on the GPU. Per-fixture color modes include emission, theme colors, ColorChord, and ColorTexture sampling against an optional scene-wide `samplingTexture` on the manager.

URP fixture prefab variants ship as standalone — the Realtime light is the sole authoring surface and drives the fixture body emissive directly via `fixtureShellRenderers`. Volumetric controls (resolution mode, modulated 3D-noise density, scene-fog coupling) and per-fixture controls (`emitterDepth`, `globalIntensity`, `targetToFollow`, `lensTransform`) are exposed on the manager and Realtime light inspectors. See `Documentation~/Realtime-Volumetric-Lights.md` and `Documentation~/Fixture-Configuration-Guide.md` for details.

Editor menu utilities:
- **VRSL → URP → Add Light Manager to Active Scene** drops a configured manager into the active scene with compute / lighting / volumetric shader references assigned.
- **VRSL → URP → Setup AudioLink Realtime Lights in Scene** configures every AudioLink mover spotlight in one click.

### Package origin

Extracted from the `urp-volumetric-lights` development branch on towneh's fork of `com.acchosen.vr-stage-lighting`, then refactored as a coexisting URP overlay package so the URP path can ship and evolve independently of the upstream VRChat-targeted package.

### Coexistence with com.acchosen.vr-stage-lighting

Hard dependency on `com.acchosen.vr-stage-lighting >= 2.8.1`. This package consumes upstream's CRT DMX decode pipeline (`_Udon_DMXGridRenderTexture*` globals), AudioLink subscription, and the legacy mesh-shader fixture geometry referenced by the URP fixture prefabs. Existing upstream scenes and prefabs continue to work alongside; this package only adds new URP fixtures and rendering, never replaces upstream assets.
